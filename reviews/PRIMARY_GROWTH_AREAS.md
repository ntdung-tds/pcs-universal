## 3. Các Vùng Cần Cải Thiện Chi Tiết (Primary Growth Areas)

Dưới đây là $3$ điểm nghẽn quan trọng nhất bạn nên rà soát và bổ sung để PCS 3.0 vận hành trơn tru khi chạy thực tế (Real-world E2E):

* **Vấn đề 1: Xung đột đồng thời (Race Condition) và Độ trễ chờ (Polling Latency) trong chế độ GitHub Inbox**
  * **Trích dẫn từ Handbook (Mục 1 — Chế độ không cần máy chủ riêng):** *"Nếu AI có quyền tạo file trong repository GitHub nhưng không chạy CLI, dùng GitHub Inbox: tạo yêu cầu tại pcs3/inbox/REQ-<id>.json, workflow xử lý, sau đó xác nhận pcs3/receipts/REQ-<id>.json có APPLIED và HEAD revision đã tăng."*
  * **Phân tích vấn đề:** Trên thực tế, một workflow GitHub Actions (`pcs3-inbox.yml`) mất trung bình từ $10\text{--}30\text{ giây}$ để khởi tạo runner (cold start), chạy `runtime/pcs3-inbox.mjs` và commit ngược lại file `receipts/REQ-<id>.json`. Các trợ lý AI trên web (ChatGPT, Claude) không có cơ chế `sleep()` tự nhiên giữa hai lần gọi tool liên tiếp — nếu AI gọi tool đọc `pcs3/receipts/REQ-<id>.json` ngay lập tức sau khi tạo file `REQ-<id>.json`, nó sẽ nhận lỗi `404 Not Found`. Ngoài ra, nếu hai yêu cầu `REQ-1.json` và `REQ-2.json` được đẩy lên cách nhau vài giây, hai tiến trình GitHub Actions chạy song song sẽ đụng độ khi cùng `git push` cập nhật `HEAD.json`.
  * **Hành động tiếp theo (Đề xuất):** Bạn đã cấu hình từ khóa `concurrency: { group: pcs3-inbox, cancel-in-progress: false }` trong `.github/workflows/pcs3-inbox.yml` chưa? Đồng thời, hãy bổ sung vào Mục 1 của Handbook quy tắc ứng xử cho AI khi chờ Receipt: *"Nếu sau lần kiểm tra đầu tiên chưa thấy `receipts/REQ-<id>.json`, AI phải báo trạng thái `INBOX_QUEUED` kèm mã `REQ-<id>` hoặc thực hiện tối đa $2$ lần đọc lại, tuyệt đối không tạo lại file `REQ` trùng lặp."*

* **Vấn đề 2: Giới hạn kích thước Payload ($1\text{ MB}$) của GitHub Contents API đối với Web AI Connectors**
  * **Trích dẫn từ Handbook (Mục 4 — Chính sách GitHub + Google Drive):** *"Mỗi byte tài liệu/ảnh/video được lưu trên GitHub trước (Contents đối với file nhỏ, draft Release asset đối với file lớn). Nếu Drive khả dụng và đúng quyền, tải thêm lên Drive và lưu liên kết vào GitHub."*
  * **Phân tích vấn đề:** Khi chạy bằng CLI cục bộ (`node runtime/pcs3.mjs`), việc đẩy file nhỏ qua Contents API và file lớn (lên tới $2\text{ GB}$) qua Draft Release Asset hoạt động hoàn hảo. Tuy nhiên, khi chạy qua **Web AI Connectors** (ChatGPT Plugin/Action, Claude Connector), AI không thể truyền trực tiếp một file nhị phân (ảnh thiết kế, video demo, hoặc file `.docx` nặng $> 5\text{ MB}$) qua JSON body của tool call vì giới hạn context/payload của LLM tool call và giới hạn cứng $1\text{ MB}$ khi ghi trực tiếp qua REST Contents API thông thường.
  * **Hành động tiếp theo (Đề xuất):** Bạn có muốn phân tách rõ chính sách lưu trữ ở Mục 4 thành hai luồng: **(a) Luồng CLI / Gateway tự host** (tải trực tiếp file lớn lên GitHub Release Asset) và **(b) Luồng Web AI không máy chủ** (với file $> 1\text{ MB}$, người dùng tải lên Google Drive hoặc GitHub Web trước, sau đó AI chỉ ghi nhận siêu dữ liệu + mã băm SHA-256 hoặc kích hoạt GitHub Actions kéo từ Drive sang GitHub Release Asset) không?

* **Vấn đề 3: Nguy cơ "Nhiễm độc ngữ cảnh" (Context Poisoning) do đóng gói kèm toàn bộ `legacy/PCS_2.1/`**
  * **Trích dẫn từ Cấu trúc gói & Handbook (Mục 1):** Trong gói `PCS_Universal_v3.0`, thư mục `legacy/PCS_2.1/` chứa hơn $70$ tệp tin (bao gồm cả `PCS_Handbook_v2.1.docx`, `KIT/starter/pcs/current.json`, và cả tài liệu từ thời v2.0 tại `REFERENCES/V2_GUIDES/`).
  * **Phân tích vấn đề:** Nhiều người dùng khi tải bộ `.zip` về sẽ có thói quen giải nén và tải toàn bộ các tệp `.md` / `.docx` lên kho tri thức (Project Knowledge của Claude hoặc Gem Knowledge của Gemini). Khi đó, LLM sẽ đọc lẫn lộn giữa quy chuẩn của **PCS 2.1** (lưu trạng thái tại `pcs/current.json`, `pcs/moments/MOM-*.json` trong từng repo dự án) và quy chuẩn của **PCS 3.0** (lưu trạng thái tập trung tại `pcs3/projects/<slug>/HEAD.json` và `events/MOM-*.json`). Điều này rất dễ làm giảm độ chính xác của AI khi khởi tạo dự án mới.
  * **Hành động tiếp theo (Đề xuất):** Trong bảng *"1. Cách bắt đầu với từng nền tảng"* của `PCS_3.0_Handbook.docx`, bạn hãy thêm một dòng cảnh báo in đậm: **"Chỉ nạp các tệp trong `adapters/` và `docs/` của PCS 3.0 vào ChatGPT/Claude/Gemini; tuyệt đối không nạp thư mục `legacy/PCS_2.1/` vào Knowledge của AI để tránh xung đột cấu trúc dữ liệu."** Ngoài ra, bạn có cân nhắc đóng gói `legacy/PCS_2.1` thành một file nén riêng (`pcs-2.1-legacy-archive.zip`) thay vì để phẳng (uncompressed folder) trong cây thư mục chính không?
